# QR共有（Beta）

時間割画面の検索横にあるQRボタンから「共有する」「読み取る」を開く。
時間割上部の日付は、ビュー切り替えの右端とQRボタンの左端の中点に揃える。QR・検索は同じ段に維持し、狭い幅では前後移動ボタンを日付へ寄せる。最小文字サイズでも収まらない場合だけ、前後移動を日付の下へ置く。
授業メモ・予定・課題は項目ごとの全画面一覧で個別にチェックを付ける。予定・課題は普段の一覧に近いカードで、期限・科目・完了状態を確認できる。
授業メモは授業日・時限の新しい順、予定・課題は期限の日付・時刻が早い順に並ぶ。完了済みは初期状態で折りたたみ、開いて選択できる。閉じている間の全選択は未完了だけを対象にし、すでに選んだ完了済み項目は折りたたんでも選択を保持する。
カメラでの連続読み取りと画像・GIFの読み込みは、ネットワーク接続を必要としない。

## 対象と置換範囲

|項目|送信対象|取り込み時の置換範囲|
|---|---|---|
|前期・後期時間割|選択年度・学期|同じ年度・学期。受信側の授業IDは維持|
|休講・授業変更|選択年度|同じ年度|
|A/B表|全件。休日・日程振替・長期休みを含む|全件。期間選択なし|
|授業メモ・予定・課題|個別選択したもの|選択した種類の全件（他年度を含む）|

未選択の種類は変更しない。全枚数を取得して検証した後、件数と上書き範囲を表示し、
明示的な確認を経てRoomトランザクションで保存する。設定・同期端末情報・トークンは共有しない。
課題・予定の端末固有ID、授業ID、カレンダーID、リマインダー設定は転送せず、通知・カレンダー連携は受信側で処理する。
時間割を含む場合、後期開始日が異なる端末への取り込みは拒否する。

## 転送形式

形式名は `SKTTP/QR`。端末間同期の `SKTTP/<version>` と独立したバージョンを管理する。

```
SKTTP/QR:1:<transferId>:<sha256>:<totalParts>:<zeroBasedPartIndex>:<base64>
```

- 選択データのJSONをUTF-8、GZIPの順で処理し、分割バイト列をBase64化する。
- 全フレームに共有ID、SHA-256、総枚数、番号を含める。順不同・重複取得を許容し、別の共有は混在させない。
- SHA-256は破損検出用であり、送信者を認証するものではない。
- カメラに見せる画面は通常1枚あたり200バイト。128枚を超える大きなデータでは、枚数上限に収まる最小の分割量へ調整する（最大512バイト）。GIFは600バイト、静止画は1600バイトまで1枚にする。
- カメラ向けの画面表示は0.2秒、GIFは0.4秒間隔でループ。画面は全画像を先に生成し、再生中は画像の切り替えだけを行う。マス数のままRGB_565で保持し、最近傍補間で拡大してメモリを抑える。画面表示は自動で繰り返し、画像共有のボタンを置く。
- 最大128枚、圧縮データ64KiB、展開JSON512KiB。入力画像16MiB、GIF128フレーム・2048px四方まで。
- 画像共有時はクラス名が必須。クラス名・年度・読み取り案内・枚数を画像に表示する。
- GIFは白黒2色の専用LZW圧縮を使い、描画バッファを再利用する。生成中は枚数を表示し、同じデータ・クラス名の再共有では作成済みファイルを使う。
- カメラは1080pを優先（非対応端末では近い解像度へフォールバック）。Y平面を行単位でコピーし、前回のQR位置を優先して1個ずつ復号する。未検出・追跡位置で読めない場合は、画面全体をそのフレームで探す。中央Shapeは画面幅の85%を基準にした目安で、読み取り範囲を制限しない。解析は既存のKEEP_ONLY_LATESTを維持する。全画面FILL_CENTER、TextureViewのCOMPATIBLEモードで表示し、初期ズームは1倍。ピンチで端末が対応する倍率範囲内を調整でき、タップでAF・AEを合わせる。
- MaterialShapesのCookie4Sided → Cookie9Sided → Sunnyをgraphics-shapesのMorphで補間する。CameraXの共通ViewPortとCoordinateTransformで、切り抜き・回転・前面カメラの反転を合わせる。認識座標は指数平滑化とspringで追従し、350ms見失った後に中央へ戻る。Cookie9Sidedの外周をPathMeasureで分割し、ユニーク受信数の進捗とパーセントを表示する。
- 周辺の見え方はAndroidのバージョンにかかわらず、Android 10と同じsoft vignetteと25%のscrimに統一する。Shapeの内部は描画を切り抜き、元のカメラ映像を鮮明に保つ。リアルタイムblurと読み取り中の映像コピーは廃止。API 33以上の成功rippleでのみ、TextureViewの再利用Bitmapを幅240pxで取得し、CameraXのTexture補正とViewの表示変換を合成する。ChoreographerとSurfaceTextureのtimestampで新しいカメラフレームだけを画面更新に同期して取得し、成功演出が終わったら取得を停止する。
- 全fragmentの復号・ハッシュ・JSON検証後に追従を止め、SunnyへのMorph、pulse、checkの表示、850msの成功rippleを1回再生してから既存の上書き確認へ進む。API 33以上は独自AGSLの波紋・映像distortion・noise sparkle、非対応時は拡張リングと小粒子を使う。アニメーション無効時は成功Shapeを即時表示する。
- 露出は中央を継続して測光し、認識したQRの位置へ測光範囲を追従させる。タップ後の手動AFを3秒間優先し、その後はAEのみを継続する。QRを1.5秒見失ったら中央へ戻し、位置の微小な揺れによる測光要求の連発を抑える。AE領域の指定に非対応のカメラでは標準の自動露出を使う。
- バックアップJSONおよび既存の同期ペイロードは変更しない。
- 画像・GIFの取り込みはAndroidの写真ピッカーから選択する。写真ピッカー非対応端末では写真ライブラリの選択画面を開く。
- 写真ボタンはQR認識中と350msの認識猶予期間もグレーアウトを維持し、フレームごとの復号の合間には有効化しない。認識が途切れ、復号・画像読み込み・インポート・確認が終了すると再び操作できる。
- `InternalFeatureFlags.QR_SHARE_BETA = false` で入口・画面・データ操作を無効化できる。

## 性能検証

2026-10-02、PCのJVM（最大ヒープ768MiB）で同じ白黒QR画像6枚（1024×1256）を圧縮。
両方式を1枚ずつウォームアップした後の1回の比較で、従来のgifencoderは4631ms、
専用エンコーダーは80msだった。描画・ファイル共有を含むAndroid実機での時間は未計測。
GIFは画像の画素一致、コード幅の境界、辞書リセット、表示間隔をユニットテストで検証する。

## 実機確認項目

- 2端末間で後期時間割とA/B表を連続読み取り。3→4→1→2、重複、欠落を確認。
- 別の共有QRが途中に入った場合、既存の受信を維持しエラーになること。
- 個別選択画面でのチェック・全選択・解除・戻る操作と、課題・予定の完了済みデータの選択を確認。
- 暗い画面、低性能カメラ、狭い端末、大きな文字での操作。
- 全画面表示・ピンチズーム・タップでのピント合わせ、端末を傾けたときのShape追従、前面カメラへのフォールバックを確認。ピンチ後に意図せずタップAFが発生しないこと、倍率が端末の上限・下限を超えないことも確認。
- 全画面の描画レイヤーからカメラへタッチを転送し、DOWNから複数指・CANCELまでを同じ受け手に渡す。Shape・進捗ラベルの上でもピンチでき、戻る・写真ボタンは通常どおり操作できることを確認。
- 新旧Androidで同じvignetteとscrimの見え方になり、Shape内部に陰影がかからないことを確認。API 33以上の成功演出でAGSLの映像distortionが動き、非対応端末では簡易rippleを使うことを確認。実機GPUでのAGSLの見た目と描画性能は未検証。
- 順不同・重複受信でも外周進捗が正しいこと、Sunny/check/ripple後に確認が出ること、アニメーション無効設定と画面離脱時の停止を確認。
- タップせずに暗い室内・明るい室内で画面のQRを読む。画面の明るさの変更、QRの移動・見失い・再認識、タップ後の自動露出への復帰、バックグラウンドからの復帰を確認。
- 多数枚のGIF生成時間、生成中の枚数表示、同じクラス名での再共有、別クラス名での再生成を確認。
- PNGとGIFを共有アプリ経由で送信し、受信した端末自身でファイルから読み込む。
- 写真ライブラリに保存されたPNGとGIFを写真ピッカーから選択して読み込む。
- カメラでQRを連続認識している間と短い見失いでは写真ボタンが点滅せずグレーアウトを維持し、認識が途切れて350ms後に再び操作できることを確認。
- 送信先でGIFが静止画化・縮小された場合、未取得枚数が表示され、取り込みできないこと。
- 確認ダイアログをキャンセルした場合、既存データが変更されないこと。
- 取り込み後、置換対象の古い通知・カレンダーイベントが消え、ウィジェットが更新されること。
- QR表示・読み取り中の回転や画面再生成では転送を最初からやり直す（Betaの制限）。
