# QR共有（Beta）

時間割画面の検索横にあるQRボタンから「共有する」「読み取る」を開く。
時間割上部の日付は、ビュー切り替えの右端とQRボタンの左端の中点に揃える。QR・検索は同じ段に維持し、狭い幅では前後移動ボタンを日付へ寄せる。最小文字サイズでも収まらない場合だけ、前後移動を日付の下へ置く。
授業メモ・予定・課題は項目ごとの全画面一覧で個別にチェックを付ける。予定・課題は普段の一覧に近いカードで、期限・科目・完了状態を確認できる。
授業メモは授業日・時限の新しい順、予定・課題は期限の日付・時刻が早い順に並ぶ。完了済みは初期状態で折りたたみ、開いて選択できる。閉じている間の全選択は未完了だけを対象にし、すでに選んだ完了済み項目は折りたたんでも選択を保持する。
カメラでの連続読み取りと画像・GIFの読み込みは、ネットワーク接続を必要としない。

## 対象と取り込み方法

|項目|送信対象|取り込み方法|
|---|---|---|
|前期・後期時間割|選択年度・学期と照合用の授業時刻設定|同じ年度・学期。受信側の授業IDは維持。時刻設定が不一致なら全体を拒否|
|試験時間割|選択年度の試験日ラベル・集合時刻・試験名・各試験の開始終了時刻・科目・担当・場所・メモ|同じ年度の試験時間割と試験日ラベル。別枠で選択でき、他の日のA/B・休日・振替は保持|
|休講・授業変更|選択年度|同じ年度|
|A/B表|全件。休日・日程振替・長期休みを含む|全件。期間選択なし|
|予定・課題|個別選択したもの|既存項目を保持し、重複しないものだけ追加|
|授業メモ|個別選択したもの|日付・時限が未登録なら追加。同じ内容はスキップ、異なる内容は個別に置換を選択|

未選択の種類は変更しない。全枚数を取得して検証した後、追加・重複件数と置換範囲を表示し、
明示的な確認を経てRoomトランザクションで保存する。照合用の授業時刻設定以外のアプリ設定・同期端末情報・トークンは共有しない。
課題・予定の端末固有ID、カレンダーID、リマインダー設定は転送せず、通知・カレンダー連携は受信側で処理する。授業への紐付けは年度・学期・曜日・時限と授業内容のハッシュを転送し、受信側の授業IDへ復元する。科目・担当・場所・毎週/A/Bの内容が異なる授業や、存在しない授業への紐付けは拒否し、時間割との同時共有を案内する。重複としてスキップした既存項目の紐付けは保持する。
通常時間割を含む場合、後期開始日と授業時刻設定（コマ数、授業・休憩・昼休みの長さ、昼休みの位置、最初の授業開始時刻、登下校時刻）を照合する。不一致や照合情報の不足は、トランザクション内で全体の取り込みを拒否する。設定の自動変更はしない。無効な登下校時刻の分は照合前に正規化する。表示・通知・カレンダー連携・その他のアプリ設定は転送しない。試験時間割は各試験の実時刻と集合時刻を転送するため、通常授業の時刻設定に依存しない。
予定・課題は科目・担当・タイトル・期限日・時・分が同じものを重複とする。科目・担当・タイトルの前後の空白は除き、担当のnullと空文字は同一視する。説明・完了状態・作成日・重要度・担当一致設定・端末固有ID・リマインダー設定は重複判定に含めず、既存項目を変更しない。同じQR内の重複も除外し、課題と予定は別々に判定する。
授業メモの競合は現在と受信した内容を表示し、未選択なら現在の内容を保持する。保存時にも最新のDB状態で重複を再判定し、確認後に編集されたメモは置換を承認していても保持する。取り込み後は実際の追加・重複・メモ置換・メモ保持件数を表示する。
追加した課題・予定だけを端末カレンダーへ登録し、既存イベントやリマインダー設定を保持する。試験時間割・試験日ラベルの変更は既存のFlowを通して授業開始通知・授業カレンダー・ウィジェットに反映する。バックアップと端末間同期のSKTTPプロトコルは変更しない。

## 転送形式

形式名は `SKTTP/QR`。端末間同期の `SKTTP/<version>` と独立したバージョンを管理する。

```
SKTTP/QR:2:<transferId>:<sha256>:<totalParts>:<zeroBasedPartIndex>:<base64>
```

- 選択データのJSONをUTF-8、GZIPの順で処理し、分割バイト列をBase64化する。
- QR形式はバージョン2へ更新した。通常時間割に必須の時刻設定、試験時間割の独立データ、課題・予定の可搬な授業参照を追加する。参照を含むJSONは最大4階層まで検証する。
- バージョン1のフレーム・JSONも読み込める。課題・予定・メモ等は従来形式から追加取り込みできるが、時刻設定を持たない旧形式の通常時間割は照合できないため拒否する。バージョン1と2の断片は混在させない。旧アプリはバージョン2に非対応のため、送受信両端末の更新が必要。
- 全フレームに共有ID、SHA-256、総枚数、番号を含める。順不同・重複取得を許容し、別の共有は混在させない。
- 読み取りエラー後はカメラ解析・画像/GIFの後続断片の解析を停止し、失敗時はテーマのerror色で外周と塗りを表示し、Cookie9SidedからSoft BurstへMorphして中央にバツを出す。700ms後に警告ダイアログを表示し、「OK」で再開する（アニメーション無効時は160ms後）。成功時のSunny・チェック・波紋は維持する。エラー中は写真ボタンも無効。破損・形式不正などでは受信断片を破棄し、別の共有ID・分割数・ハッシュでは元の受信断片を保持する。どちらも「OK」で収集状態を初期化して再開する。既存データは変更しない。
- SHA-256は破損検出用であり、送信者を認証するものではない。
- カメラに見せる画面は通常1枚あたり200バイト。128枚を超える大きなデータでは、枚数上限に収まる最小の分割量へ調整する（最大512バイト）。GIFは600バイト、静止画は1600バイトまで1枚にする。
- カメラ向けの画面表示は、全ユーザーが「安定（200ms）」「標準（125ms）」「高速（65ms）」「超高速（50ms）」を切り替えられる。初期選択は標準。曜日切替と同じAppConnectedButtonGroupを使い、超高速の選択・解除時は赤系のテーマ色へ滑らかに遷移する。狭い画面や文字倍率増加時は横スクロールでボタン名を保つ。画面は全画像を先に生成し、速度変更でも画像を作り直さない。マス数のままRGB_565で保持し、最近傍補間で拡大してメモリを抑える。GIFは0.4秒間隔でループする。
- IntDev向けの容量・速度調整と設定ボタンは撤去し、過去の保存値も使用しない。画面表示の分割量は200バイトを基準とし、128枚の上限を守る容量自動調整を維持する。画像・GIF共有の容量・速度は変更しない。
- 最大128枚、圧縮データ64KiB、展開JSON512KiB。入力画像16MiB、GIF128フレーム・2048px四方まで。
- 画像共有時はクラス名が必須。クラス名・年度・読み取り案内・枚数を画像に表示する。
- GIFは白黒2色の専用LZW圧縮を使い、描画バッファを再利用する。生成中は枚数を表示し、同じデータ・クラス名の再共有では作成済みファイルを使う。
- カメラは1080pを優先（非対応端末では近い解像度へフォールバック）。ZXing-C++ 3.1.1でY平面を直接読み取り、前回のQR位置を優先して1個ずつ復号する。pixelStrideが1でない場合や非directバッファだけ連続画素へコピーし、rowStride・bufferのposition/limitを尊重する。未検出・追跡位置で読めない場合は、ViewPort全体をそのフレームで探す。中央Shapeは画面幅の85%を基準にした目安で、読み取り範囲を制限しない。解析は既存のKEEP_ONLY_LATESTを維持する。全画面FILL_CENTER、TextureViewのCOMPATIBLEモードで表示し、初期ズームは1倍。ピンチで端末が対応する倍率範囲内を調整でき、タップでAF・AEを合わせる。
- MaterialShapesのCookie4Sided → Cookie9Sided → Sunnyをgraphics-shapesのMorphで補間する。CameraXの共通ViewPortとCoordinateTransformで、切り抜き・回転・前面カメラの反転を合わせる。認識座標は指数平滑化とspringで追従し、350ms見失った後に中央へ戻る。Cookie9Sidedの外周をPathMeasureで分割し、ユニーク受信数の進捗とパーセントを表示する。
- 読み取り中の周辺表示は全Androidでsoft vignetteと25%のscrimに統一し、Shape内部は鮮明に保つ。受信・検証が完了したときだけ、API 31以上では8dpの背景blurへ400msで滑らかに移行する。ぼかしはカメラ背景だけに描画し、Sunny・チェック・操作部は鮮明なまま。非対応端末・GPU非対応・映像取得失敗時は背景の陰影を徐々に強める。アニメーション無効時は即時表示し、読み取りを再開するとぼかしを解除する。成功時のblurとAPI 33以上のrippleではTextureViewの再利用Bitmapを幅240pxで取得し、CameraXのTexture補正とViewの表示変換を合成する。ChoreographerとSurfaceTextureのtimestampで新しいカメラフレームだけを取得し、移行・波紋が終わったら取得を停止して最後の背景を保持する。映像が得られない場合も1.2秒で取得を打ち切る。読み取り中の映像コピーは行わない。
- 全fragmentの復号・ハッシュ・JSON検証後に追従を止め、SunnyへのMorph、pulse、checkの表示、850msの成功rippleを1回再生してから取り込み確認へ進む。API 33以上は独自AGSLの波紋・映像distortion・noise sparkle、非対応時は拡張リングと小粒子を使う。アニメーション無効時は成功Shapeを即時表示する。
- 露出は中央を継続して測光し、認識したQRの位置へ測光範囲を追従させる。タップ後の手動AFを3秒間優先し、その後はAEのみを継続する。QRを1.5秒見失ったら中央へ戻し、位置の微小な揺れによる測光要求の連発を抑える。AE領域の指定に非対応のカメラでは標準の自動露出を使う。
- バックアップJSONおよび既存の同期ペイロードは変更しない。
- 画像・GIFの取り込みはAndroidの写真ピッカーから選択する。写真ピッカー非対応端末では写真ライブラリの選択画面を開く。
- 写真ボタンはQR認識中と350msの認識猶予期間もグレーアウトを維持し、フレームごとの復号の合間には有効化しない。認識が途切れ、復号・画像読み込み・インポート・確認が終了すると再び操作できる。
- 総枚数が3枚以上の場合、最初の1枚を受信してから1.5秒間、枚数の横に「そのまま向けてください」を表示する。追加受信・重複検出で表示時間は延長しない。途中でQRを見失って中央のCookie4Sidedへ戻った場合は、受信済みの外周進捗だけを表示し続け、枚数・パーセント・案内は隠す。再認識すると枚数・パーセントを再表示する。
- 外周進捗の開始位置はShape上の周長比として固定し、Morph・移動・回転中に最上点を選び直さない。中央復帰には直前の角度に最も近い0度相当を使い、進捗の開始位置の飛びと余分な回転を防ぐ。
- 上部タイトルの右側にfragmentごとのドットを表示する。Collectorの0始まりindexを安定したkeyにし、常に番号の昇順で並べる。5dpのドットと4dpの間隔から横幅に応じて最大3行の容量を計算し、3行目だけに画面外の数（+N）の領域を確保する。unique受信時だけ1.3倍の短いpulseを行い、overflowがある間だけ受信済みドットをpulse後にslide/fadeで退場させる。未受信は退場させず、後続を昇順のまま詰める。画面外で受信済みのfragmentもCollectorの状態を使い、後から表示されても再pulseしない。残りが一度3行以内になったら退場を終了し、穴埋め用の固定表示になる。+Nが0になったらfade outする。中央UIと完了演出は維持する。
- カメラの回転・白黒反転・縮小探索はZXing-C++へ任せる。アプリ独自の90/180/270度画像生成と再解析は撤去する。C++が返すQRの実際の四隅を追跡に使用し、元のバッファ向き・ViewPort内座標へ揃えてCameraXへ渡す。JNIはAndroid専用なので復号テストはandroidTestに置き、15度刻みの回転、ぼけ・ノイズ・反転、追跡外への移動、crop・stride・buffer位置・カメラ向きの組み合わせを実機で検証する。追跡領域とY平面の検証はJVMテストを維持する。QR生成・保存画像/GIFの読み込みにはJava版ZXingを引き続き使用する。
- `InternalFeatureFlags.QR_SHARE_BETA = false` で入口・画面・データ操作を無効化できる。

## 性能検証

2026-10-02、PCのJVM（最大ヒープ768MiB）で同じ白黒QR画像6枚（1024×1256）を圧縮。
両方式を1枚ずつウォームアップした後の1回の比較で、従来のgifencoderは4631ms、
専用エンコーダーは80msだった。描画・ファイル共有を含むAndroid実機での時間は未計測。
GIFは画像の画素一致、コード幅の境界、辞書リセット、表示間隔をユニットテストで検証する。

## 実機確認項目

- 2端末間で後期時間割とA/B表を連続読み取り。3→4→1→2、重複、欠落を確認。
- 別の共有QRが途中に入った場合、既存の受信を維持しエラーになること。
- 個別選択画面でのチェック・全選択・解除・戻る操作と、課題・予定の完了済みデータの選択を確認。
- 暗い画面、低性能カメラ、狭い端末、大きな文字での操作。
- 全画面表示・ピンチズーム・タップでのピント合わせ、端末を傾けたときのShape追従、前面カメラへのフォールバックを確認。ピンチ後に意図せずタップAFが発生しないこと、倍率が端末の上限・下限を超えないことも確認。
- 全画面の描画レイヤーからカメラへタッチを転送し、DOWNから複数指・CANCELまでを同じ受け手に渡す。Shape・進捗ラベルの上でもピンチでき、戻る・写真ボタンは通常どおり操作できることを確認。
- 新旧Androidで同じvignetteとscrimの見え方になり、Shape内部に陰影がかからないことを確認。API 33以上の成功演出でAGSLの映像distortionが動き、非対応端末では簡易rippleを使うことを確認。実機GPUでのAGSLの見た目と描画性能は未検証。
- 順不同・重複受信でも外周進捗が正しいこと、Sunny/check/ripple後に確認が出ること、アニメーション無効設定と画面離脱時の停止を確認。
- タップせずに暗い室内・明るい室内で画面のQRを読む。画面の明るさの変更、QRの移動・見失い・再認識、タップ後の自動露出への復帰、バックグラウンドからの復帰を確認。
- 多数枚のGIF生成時間、生成中の枚数表示、同じクラス名での再共有、別クラス名での再生成を確認。
- PNGとGIFを共有アプリ経由で送信し、受信した端末自身でファイルから読み込む。
- 写真ライブラリに保存されたPNGとGIFを写真ピッカーから選択して読み込む。
- カメラでQRを連続認識している間と短い見失いでは写真ボタンが点滅せずグレーアウトを維持し、認識が途切れて350ms後に再び操作できることを確認。
- 送信先でGIFが静止画化・縮小された場合、未取得枚数が表示され、取り込みできないこと。
- 確認ダイアログをキャンセルした場合、既存データが変更されないこと。
- 取り込み後、既存の課題・予定・他年度のメモ・完了状態・通知設定・カレンダーイベントが保持され、追加分だけカレンダーに登録され、ウィジェットが更新されること。同じQRを再度取り込んでも課題・予定が増えないこと。
- 同じ日付・時限の異なるメモで現在と受信内容を確認でき、選択したものだけ置き換わること。確認中に別経路で編集されたメモは保持され、結果件数にも反映されること。
- 試験時間割だけを共有し、他年度の試験・通常時間割・他の日のA/B設定を保持しつつ試験日と集合時刻・各試験・メモが反映されること。
- 通常時間割と時刻設定の一致・不一致、旧形式で照合情報がない場合を確認。不一致時は同時に選んだ課題・予定・メモも含め、一切保存されないこと。
- 課題・予定だけの共有、時間割との同時共有で、送信元と異なる受信側IDへ授業の紐付けが復元されること。紐付け先が未登録または内容が違う場合は、全体がロールバックされること。
- QR表示・読み取り中の回転や画面再生成では転送を最初からやり直す（Betaの制限）。
